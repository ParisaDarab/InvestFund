# Data model

PostgreSQL 16 + Prisma 6. Source of truth: `apps/api/prisma/schema.prisma` and its migrations.
The v1 model is archived in `archive/DATABASE_v1.md`.

## 1. Conventions

- Tables are snake_case plural and columns snake_case. Ids are UUID v7 generated by the app
  (`core/ids`), so they sort in creation order.
- Timestamps are `timestamptz` in UTC. Calendar dates (deadlines, milestone dates) are `date`.
- Money is a BIGINT in minor units (`*_minor`) plus a `currency char(3)`, with CHECK constraints
  for positivity and format. No floats.
- Enums are lower-case Prisma enums. Values are identical in the API.
- Free-text columns have explicit `varchar(n)` limits that match the Zod schemas.

## 2. Entities

| Table | Purpose | Key constraints |
|---|---|---|
| `users` | Google identity, role, status, email preference | unique `email` (citext), unique `google_sub` |
| `sessions` | Refresh sessions (SHA-256 of the token, rotation, reuse detection) | unique `token_hash`; cascade on user delete |
| `founder_profiles` | Founder public profile (1:1 user) | PK `user_id` |
| `supporter_profiles` | Supporter profile and matching preferences (consolidates SupporterPreference) | CHECK range ordered and positive |
| `startups` | Listing: content, funding plan, status, version | unique `slug`; CHECKs for positive amounts and `min ≤ max`; indexes for discovery |
| `startup_milestones` | Ordered funding milestones | CHECK amount > 0; cascade with startup; restrict while an offer references it |
| `saved_startups` | Supporter bookmarks | PK (user, startup) |
| `connections` | Supporter → startup request and status | **partial unique (startup, supporter) WHERE status IN (pending, accepted)** |
| `conversations` | One per accepted connection | unique `connection_id` |
| `conversation_participants` | Membership and `last_read_at` | PK (conversation, user) |
| `messages` | Persisted chat messages | unique (sender, client_message_id); index (conversation, created_at desc, id) |
| `deals` | Negotiation and outcome state, `version`, current and accepted offer | **partial unique (connection) WHERE status = negotiating**; unique current/accepted offer |
| `offers` | Immutable offer revisions | unique (deal, revision); unique `previous_offer_id` (linear chain); CHECK amount > 0, creator ≠ recipient |
| `offer_milestones` | Milestones an offer funds | PK (offer, milestone) |
| `deal_events` | Append-only negotiation and outcome history | index (deal, created_at) |
| `notifications` | In-app notifications | unique (user, dedupe_key); index (user, created_at desc) |
| `email_outbox` | Transactional email queue | unique `dedupe_key`; index (status, next_attempt_at) |
| `startup_documents` | Document metadata; binary in private storage | unique `storage_key`; soft delete `deleted_at` |
| `document_grants` | Explicit access to `selected` documents | PK (document, connection) |
| `user_blocks` | Blocks | PK (blocker, blocked); CHECK not self |
| `reports` | Reports about users and startups, plus the admin resolution | CHECK the target matches `target_type` |
| `audit_events` | Append-only audit trail (no secrets or message text) | indexes by entity, actor and time |
| `rate_limit_buckets` | Rate-limit counters (P0) | unique (preset, key_hash) |

Sector, stage, purpose, country and report-category values are controlled vocabularies held in
`packages/shared/src/domain/taxonomy.ts` and stored as varchar.

## 4. Deletion and archival

- Startups are archived, never deleted, by the app. Milestones cascade with a startup, but
  deletion is restricted while an offer references them.
- Connections, deals, offers, messages and events are kept as history (`ON DELETE RESTRICT` from
  users). User deletion and erasure is a P1 workflow that will need anonymisation; see
  `OPERATIONS.md` §Legal.
- Documents are soft-deleted in the database and hard-deleted in storage.
- Sessions and expired rate-limit rows may be purged at any time.

## 5. Migrations

- `20261009000000_init_extensions`: `vector`, `citext`.
- `20261009201159_rate_limit_buckets`
- `20261010202650_marketplace_domain`: every table above, plus the SQL-only partial unique
  indexes and CHECK constraints.

Deploy with `prisma migrate deploy` (never `migrate reset` against shared data). Seeding is
idempotent and synthetic (`infra/seed/seed.ts`).
